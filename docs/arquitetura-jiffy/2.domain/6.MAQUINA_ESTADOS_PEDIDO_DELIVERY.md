# Máquina de estados do pedido delivery

Este documento formaliza a etapa operacional do pedido no Gestor.  
É a fonte normativa para Kanban, fiscal, impressão e edição de itens.

## 1. Vocabulário canônico

A etapa operacional é o value object `EtapaOperacionalDelivery`.

Valores (`statusDelivery` da API):

| Etapa        | Significado                         |
|--------------|-------------------------------------|
| `PENDENTE`   | Novo pedido, ainda sem preparo      |
| `EM_PREPARO` | Cozinha / produção                  |
| `PRONTO`     | Pronto para expedição / retirada    |
| `EM_ROTA`    | Saiu para entrega                   |
| `FINALIZADO` | Entregue ou retirado                |
| `CANCELADO`  | Encerrado sem conclusão             |

Não usar outro vocabulário de etapa (coluna do Kanban não é estado persistido).

Não usar id de coluna do Kanban como status persistido.

## 2. Transições

Ações do Gestor (`AcaoTransicaoOperacionalDelivery`) → etapa:

| Ação              | Destino      |
|-------------------|--------------|
| `iniciar_preparo` | `EM_PREPARO` |
| `marcar_pronto`   | `PRONTO`     |
| `despachar`       | `EM_ROTA`    |
| `finalizar`       | `FINALIZADO` |
| `cancelar`        | `CANCELADO`  |

Cancelar é permitido em qualquer etapa em curso.  
Não cancelar pedido já `FINALIZADO` ou `CANCELADO`.

## 3. Coluna do Kanban (só projeção)

| Etapa        | Coluna            |
|--------------|-------------------|
| `PENDENTE`   | `NOVOS_PEDIDOS`   |
| `EM_PREPARO` | `EM_PREPARO`      |
| `PRONTO`     | `PRONTO_ENTREGA`  |
| `EM_ROTA`    | `EM_ROTA`         |
| `FINALIZADO` / `CANCELADO` | `FINALIZADAS` (pool; filtros fiscais na UI) |

Colunas fiscais (`PENDENTE_EMISSAO`, `COM_FISCAL`, `REJEITADAS`) não são etapa operacional.

## 4. Regras que leem a etapa

- Fiscal delivery: emitir só se `FINALIZADO`. Etapa em curso bloqueia. Sem etapa parseável → `indeterminado`.
- Editar itens: só `PENDENTE`, `EM_PREPARO`, `PRONTO`.
- Impressão automática: `iniciar_preparo` / `marcar_pronto` (application), sem conhecer coluna de UI.

## 5. Alias fechados no parse

`EtapaOperacionalDelivery.tryParse` aceita só sinônimos documentados:

- gênero: `FINALIZADA`, `CANCELADA`
- coluna: `NOVOS_PEDIDOS`, `PRONTO_ENTREGA`, `FINALIZADAS`
- persistência antiga: `ENTREGUE`, `CONCLUIDO`, `DESPACHADO`, `SAIU_PARA_ENTREGA`, `SAIU_ENTREGA`

Qualquer outro texto (`COZINHA`, `NOVO`, `ROTA`) não é etapa.

## 6. Status fiscal canônico

Value object `StatusFiscalVenda` (`statusFiscal` da listagem / resumo).

| Status                 | Significado                    |
|------------------------|--------------------------------|
| `PENDENTE`             | Enviada, aguardando SEFAZ      |
| `PENDENTE_AUTORIZACAO` | Idem (nome da API)             |
| `EMITINDO`             | Emissão em andamento           |
| `CONTINGENCIA`         | Contingência                   |
| `PENDENTE_EMISSAO`     | Ainda sem tentativa            |
| `EMITIDA`              | Autorizada                     |
| `REJEITADA` / `DENEGADA` | Recusada                     |
| `CANCELADA`            | Nota cancelada                 |
| `INUTILIZADA`          | Numeração inutilizada          |

Alias: `AUTORIZADA`/`AUTORIZADO` → `EMITIDA`; `EM_PROCESSAMENTO` → `PENDENTE_AUTORIZACAO`.

Regras: emitir delivery só após etapa `FINALIZADO`; aba/PDF/cancelar nota usam o VO, não `Set<string>`.

`NFeStatus` da entidade é este mesmo vocabulário.

## 7. Outras máquinas (não misturar)

- `StatusVenda`: `ABERTA` \| `FINALIZADA` \| `PENDENTE_EMISSAO` (venda, não logística).
